# 1.3.0

* Offical Steam Workshop Support coming with 1.3.0 release! To support Steam Workshop, we've added an in-game mod list which shows all installed mods and their statuses. The mod list can also be used by quickly navigate to your mods sources by clicking on them or to re-order the loading order of mods in-game. If a mod has failed to compile there will be a tooltip which will tell you if your mod failed to compile or was missing a dependency, if you click on that tooltip you'll immediately be taken to the `Player.Log` file where you can find more detailed information.
* Moddable Custom Scenes! You may now create your own, unique custom scenes and add them to the game via a mod.
* EntityAuthoringDataBlock is a new `ScriptableDataBlock` type which stores a soft reference to an Entity prefab. You may overload these datablock instances to mod existing entities, or create new ones. Where an entity prefab was previously referenced you will now have to create an `EntityAuthoringDataBlock` instance, reference your entity prefab to that instance and then reference the instance itself. (see the bottom of this change list for migration scripts!)
* GraphicalObjectDataBlock is a new `ScriptableDataBlock` type which stores a soft reference to a Graphical prefab, as well as pool settings for that prefab. You may overload these datablock instances to mod existing graphical objects, or create new ones. Where a graphical prefab was previously referenced you will now have to create a `GraphicalObjectDataBlock` instance, reference your graphical prefab to that instance and then reference the instance itself. (see the bottom of this change list for migration scripts!)
* ParticleEffectDataBlock is a new `ScriptableDataBlock` type which stores a soft reference to a Particle prefab, as well as pool settings for that prefab. You may overload these datablock instances to mod existing particles, or create new ones. `ParticleEffectIDs` are now deprecated and you should use `ParticleEffectDataBlock` instances in their place. `PuffID` is still used, to the same extent as before.
* PoolParameterDataBlock is a new `ScriptableDataBlock` type which stores the graphical object pooling size. You may either create new ones with unique parameters or re-use existing ones by assigning them from the `Core Keeper Assets` package. This is the new and supported way to pool objects. `PooledObjectBank` is now deprecated.
* TilesetDataBlock is a new `ScriptableDataBlock` type which stores references to Tileset textures and their adaptive tileset textures. To mod a tileset you would have to assign a new Tileset texture and regenerate the adaptive tileset textures at the bottom of your `TilesetDataBlock` instance. Note that the references on these `TilesetDataBlock` instances are addressable texture2D references, meaning that you'll need to create addressables settings first. It's crucial that when you do create addressables settings that you select Ignore when prompted with what to do with legacy bundles. Once you've set up addressables settings you may mark any tilesets which you want to use as addressable. You may then reference them on the `TilesetDataBlock` instances.
* CustomSceneDataBlock is a new `ScriptableDataBlock` type which is used for custom scene creation. Upon creating a new instance of this datablock type you will be able to press `Create scene from template` to get started with Custom Scene creation. Within that same datablock instance there is data stored of where which prefabs should be placed and such, this data will be automatically populated when scenes are processed during mod building so only edit this data in advanced use cases.
* ObjectIDCategoryDataBlock is a new `ScriptableDataBlock` type which stores all of the game's `Object ID Categories`, these are primarily used for displaying objects categories in the editor as well as in creative mode menu to determine where which objects should appear when searching for a building block as an example.
* MapMarkerIconDataBlock is a new `ScriptableDataBlock` type which stores references to map marker icons.
* BehaviourTagsDataBlock is a new `ScriptableDataBlock` type which stores NPC behaviour tags as a list.
* CursorSkinDataBlockCollection is a new `Scriptable Data Collection` which stores references to `Sprite Assets` and `Sprite Asset Skins` for Cursor recolors. To add new recolors you may simply add a new instance of a `Sprite Asset Skin` and add to this collection.
* Example Mods have been consolidated into fewer, larger example mods. The documentation to reflect these changes and more will be uploaded to GitBook when `1.3.0` is officially released.
* Steam Workshop mods can now be uploaded to Steam Workshop without initializing the Core Keeper app via Unity. This is done by using an external app through Unity to handle the uploading process itself.
* Within the ModSDK, the Mod.IO interface has been refactored to fall more in line with the Steam Workshop interface. This has also resulted in multiple bug fixes such as sometimes not being able to upload an image or to upload the mod.
* Game versioning for mods will now happen automatically by tagging mods with the game version retrieved when updating game files. IE a mod which was made using the `1.3.0` game version will automatically be tagged with the `1.3.0` game version when being uploaded to Steam Workshop or Mod.IO.
* `OverrideNetworkSyncDistanceAuthoring` is deprecated in favor of `OverrideClientSyncScreenDistanceAuthoring`. You now also have the option to implement `INetworkSyncDistanceProvider` directly on an authoring component if values in that component indicate how far away entities need to be synchronized to clients.
* Added `LightSourceAuthoring` as a replacement for `ActAsLightSourceWhenHeldInHandAuthoring`, `GlowLightAuthoring`, and `TableItemLightSourceAuthoring`, all of which are now deprecated. This new component implements `INetworkSyncDistanceProvider`, meaning placeable light sources using this will automatically be synced correctly when in range.
* `BehaviourTagsAuthoring` now uses `BehaviourTagsDataBlock`. The previous fields in `BehaviourTagsAuthoring` still exist but are still available (hidden) to support upgrading existing content.
* `ObjectInfo.prefabInfos` has been deprecated and will be removed in a future update. Replaced with authoringRef and graphicalRef for EntityAuthoringDataBlock refs and GraphicalObjectDataBlock refs respectively.
* `ObjectAuthoring.graphicalPrefab` has been deprecated and graphicalRef should be used in it's place.
* `ParticleEffectID` has been deprecated in favor of ParticleEffectDataBlock instances.
* `MapWorkshopTilesetBank` has been refactored into instances of TilesetDataBlock.
* `CustomScenesTable` and `CustomScenesDataTable` have been refactored into instances of CustomSceneDataBlock.
* `OnSpawn` should now be used to call any functions relative to modifying an entity, instead of `OnOccupied`.
